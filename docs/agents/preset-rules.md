# Rule types and Preset Rules

Moved out of `AGENTS.md`: read it when working on this area.

A Program's or Group's Rule is an App Rule or a Preset Rule (`RulesWindow` selects by a mask of `Rule::ruleTypeBit()`; the driver doesn't know the rule types). The default Preset Rules are in `ui/conf/rule/presets.json` (a stable `code`, English names and notes only; a combining one lists its sub-presets by the codes listed before it, with the Terminating Block; every preset has `since`, the file's version adding it; `ConfUtilTest.defaultPresetRules` validates them), marked by their codes in the conf DB's `rule.preset_code` (not set by the Edit Rule dialog: a duplicate is the user's rule; the dialog asks to confirm saving a default preset's changes, but of its Enabled and Tray Menu flags: `RuleRow::defaultPreset`) and synced by `PresetRulesManager` (`conf/`, a friend of `ConfRuleManager`; by `ConfRuleManager::syncPresetRules()`, which writes the rules to the driver and signals their change, also the ones synced till an error, on the start too: the driver gets the rules before the conf's load): on a new conf and by the Rules window's "Add Default Preset Rules" (`addDefaultPresetRules()`, RPC: also the ones deleted by the user), on the master's start (`ConfManager::setupDefaultPresetRules()`: only when the file's `version`, YYYYMMDDNN compared as a string, is newer than the one synced last, FortFirewall.ini's `base/rulePresetVersion`; without it an old conf, without the coded rules, gets them all, as a new conf, and a conf with them, the .ini reset, is synced but gets no missing ones; a missing preset is added only when its `since` is newer: else the user deleted it). An existing preset is updated to the file's one, the user's edits are lost, except its Enabled and Tray Menu flags (`PresetRulesManager::keepUserFlags()`; the sub-presets deleted by the user stay deleted); one removed from the file becomes the user's rule: its code is cleared. Change a preset's content in the file freely, bumping the file's `version`; keep its code (a new code is a new preset, with `since` set to the new `version`).
