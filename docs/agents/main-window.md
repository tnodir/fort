# Main window

Moved out of `AGENTS.md`: read it when working on this area.

The Main window (`form/main/`, `MainWindow`, `WindowMain`, the first `WindowCode`, shown without the password) is a `FormWindow` with a header (`MainWindow::setupHeader()`: the menu bar `MainMenuBar` above the tool bar `MainToolBar`, the compact `LogoWidget` beside both) above a dock host: a `QMainWindow` embedded as a child widget (`Qt::Widget`), whose central widget is only the hint shown while there are no docks. It replaced the My Fort window and is named "My Fort" in the UI (its title is the application's name): it is opened by the tray's "My Fort" action (`tray::ActionShowMain`, also selectable as a click action, its hot key `HotKey::main`; the My Fort window's ini values, the click action `Home` and `hotKey/home`, are migrated by `UserSettings` and `actionTypeByName()`), `-c window show main` (and `home`) and `-c home show`, which a second launch posts (`WindowManager::exposeMainWindow()`). While the tray icon is hidden it is shown on startup and its closing quits (`IniUser::mainWindowAutoShowWindow()`, `MainWindow::checkAboutToClose()`); Closing it closes its docked windows, not the separate ones (`MainWindow::onWindowClosed()` → `WindowManager::closeDockedWindows()`); Esc doesn't close it (`closeOnEscape()`).

## Docking

The dockable windows are `WindowDockable` (`form/form_types.h`): Programs, Services, Rules, Traffic, Activity, Connections, Zones, Groups, Speed Limits, Time Periods. The Activity window is docked by default (`IniUser::windowDocked()`'s default) and restored docked with a new ini's Main window (`IniUser::mainWindowDocks()`'s default list). Only the windows themselves are docked: their variants (`AppConnsWindow`, the Rules window's select mode: `RulesWindow::isDockable()`) and the edit dialogs are always windows. A window has two states, docked or a top-level window: no floating docks (`PanelDock` is `DockWidgetFloatable` only to be dropped outside the Main window: `PanelDock::onDroppedFloating()` undocks it there by `WindowManager::undockWindowByCode()` with the drop place, or puts it back by `setFloating(false)` when dropped over the Main window; a double click on its title bar does nothing).

The window itself becomes the dock's widget (`PanelDock`, its `objectName()` the window's `iniGroup()`), and is re-parented back to a top-level window on undocking (`PanelDock::takeFormWindow()`): there is no page/shell split. `FormPointer` still owns the window (its `unique_ptr`) while the dock is its parent, so the window is always taken out of the dock before it's closed or deleted (`FormPointer::close()` → `takeFromDock()`).

- `FormPointer::show()` shows a window docked when its ini group's `docked` flag is set (`IniUser::windowDocked()`): it shows the Main window first, which adds the dock (`MainWindow::addDock()`, tabified with the focused dock or the last one). So the tray, `-c` and the menus open a window where it was last.
- `FormPointer::moveToDock()` / `moveToWindow()` (`WindowManager::dockWindowByCode()` / `undockWindowByCode()`) set the flag and move the window. The buttons: the `WindowMenuButton`'s menu (its arrow icon, without the style's menu indicator: `initStyleOption()`; its "Help" item too, opening its `FormWindow`'s `helpSection()` with F1 shown as the window's F1, and "Close"), "Dock to My Fort" in the window's header (`HeaderButtons::windowMenuButton()`, shown only for a dockable window by `FormWindow::setupWindowMenuButton()`) and "Undock from My Fort" in the dock's title bar beside its "Close" button (`setDocked(true)`; the title bar's right click shows the same menu instead of the dock host's `createPopupMenu()`). The Window menu has no windows: the tool bar's header buttons open them; its items are "Installation" (opening the Installation window, `form/install/`, `WindowInstallation`: the driver, the service, the portable uninstall and the integrations, the My Fort window's page) and "Reset Layout" (`MainWindow::resetDocksLayout()`) re-adds the open docks as tabs of one group, as `addDock()` adds them, the focused one staying the current tab.
- A docked window's header (the row of its controls above its contents, `FormWindow::createHeaderWidget()`) is shown in the dock's title bar, between the title and the window menu button (`PanelDock::setupTitleBar()`: `FormWindow::takeHeaderWidget()`, given back by `restoreHeaderWidget()` on undocking). It doesn't set the dock's minimum width: a `ClipContainer` lays it out at least at its minimum width and clips the rest, the title isn't shrunk. The dock has the window's actions too (`addActions()`), so its shortcuts work while the focus is in the header.
- `FormWindow::changeEvent(QEvent::ParentChange)` → `updateDocked()`: a docked window hides its header buttons (Options, Statistics, Menu: the tool bar has them) and disables its own F1 action (`FormWindow::helpAction()`: the Main window's one, the Help menu's Help action, resolves the help section by the focused dock: `MainWindow::helpSection()`) and drops its own minimum size till undocked (`updateDockedMinimumSize()`): the dock host shows no drop place where the docks' minimum sizes don't fit (`QMainWindowLayout::hover()`), and a dock dropped without one over the Main window returns to its place. `FormPointer::moveToWindow()` re-applies the "Exclude from capture" option and the taskbar badge to the undocked window's new native window.
- `FormPointer::isShown()` counts a docked window as shown, even when hidden in its tab.
- A docked window's action shortcuts are scoped to it (`Qt::WidgetWithChildrenShortcut`, `FormWindow::setupActionShortcuts()`), else the same shortcut of two docked windows would be ambiguous. Esc closes only a top-level window (`WidgetWindow::closeOnEscape()`).
- `WidgetWindowStateWatcher` ignores a docked window's geometry: a window keeps its own geometry (`FormWindow::saveIniWindowGeometry()` by its ini group) for when it's undocked.

## Layout

`MainWindow::saveWindowState()` saves the docks' ini groups (`IniUser::mainWindowDocks()`) and the dock host's `saveState()` (`mainWindowDocksState()`, `DOCKS_STATE_VERSION`). On showing, `MainWindow::restoreDocks()` (queued after the window is shown) shows the saved groups' windows by their codes (the `dockWindows` table) and calls `restoreState()`, which finds the docks by their object names; a window shown on request stays the current tab. The docked windows are restored without the password (`WindowManager::restoreDockedWindowByCode()`, `FormPointer::restoreDocked()`): while it is required `MainWindow::updateLocked()` keeps the whole dock host disabled (the docks with their title bars and tabs), and `WindowManager::windowOpened()` doesn't count it as unlocked (`WindowPasswordUnlocking`), else it would unlock the other windows; `WindowManager::onPasswordCheckedChanged()` counts the opened ones when the password is checked. On quit `WindowMain`, the first in `WindowManager::m_forms`, saves the layout before the docked windows are closed.

## Menu bar and tool bar

`MainMenuBar` (File, Tools, Window, Help) adds the tray's actions (`TrayIcon`'s accessors) instead of new ones: they keep their state, icons, texts and hot keys, and their hot keys work in the Main window too. So the windows opened by the tool bar's menus follow the tray's "Switch window" option (`IniUser::traySwitchWindow()`). The menus have no mnemonics: the docked windows use Alt+letter shortcuts (the Programs window's Alt+A/B/S). The File menu has Lock and Unlock and the Backup submenu (Export, Import, Import new programs: `BackupController`, moved from the Options window), which is disabled while the password is required (`MainMenuBar::setLocked()` by `MainWindow::updateLocked()`). An import closes all the windows, the Main window too (`ConfManager::importBackup()`). The Help menu's links are `AppLinks` (`form/controls/applinks.h`); its "Check for Updates" opens the Updates window (`form/update/`, `WindowUpdates`, the My Fort window's About tab, also opened by the new version's tray message and the Update Checker task's double click), "About" shows `WindowManager::showAboutBox()`. The Updates window (like the Installation one) is password-protected (`WindowPasswordProtected`, so it keeps the password unlocked while it is open). The About box isn't protected. Its Help action is the Main window's F1 action (`FormWindow::helpAction()`): F1 does nothing in an open menu, as any shortcut (Qt applies no window's shortcuts while a popup is active).

`MainToolBar` (not movable: it isn't in a `QMainWindow`'s tool bar area) has the firewall's switches, the tray's actions too: Filter Enabled, and the Block Traffic and Filter Mode menus as icon-only instant-popup buttons (`menuAction()`), whose icon and tool tip are of the selected item (`selectMenuAction()` in `trayicon.cpp`); then, after a separator, the `InstallationButton` (opening the Installation window) and the header buttons (`HeaderButtons`: Options, Statistics, Menu), which the docked windows hide.
