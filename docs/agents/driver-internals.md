# Driver internals (`src/driver/`)

Moved out of `AGENTS.md`: read it when working on this area.

## Files

`fortdrv.c` entry point; `fortcout.c` WFP callouts registration, `fortcout_ale.c` ALE and `fortcout_pkt.c` packet classify callouts; `common/fortconf_conn.c` the ALE connection's decision (local addresses, flags, addresses, Filter Mode, App, Zones, Rules, Groups), shared with the UI (`DriverCommon::confConnFilter()`, used by the Filter Simulator: `FilterSimulator` writes the conf buffers as for the driver, a client asks the service by RPC) and accessing the conf via callbacks, so the driver keeps its locks; `fortcnf*.c` the live configuration (conf/rules/groups/zones) with reader-writer locks; `fortbuf.c` the log ring buffer read back by the UI; `fortpkt.c` packets' cloning and re-injection, `fortpkt_shaper.c` the Speed Limits' shaper queues, `fortpkt_pending.c` the pended (Ask to Connect) packets; `fortstat.c` traffic accounting; `fortps.c` process tracking, `fortpsname.c` the processes' names, interned with their references (the equal names are the same one); `fortpool.c`/`forttlsf.c` allocators (TLSF from `src/3rdparty/tlsf`); `fortmod.c` + `loader/` the self-loading module (fortfwdl.sys unpacks the signed payload); `proxycb/` callout trampolines (with .asm variants per arch).

## The ALE connection's decision

The ALE callout decides a connection by `fort_callout_ale_check_conf()`: `fort_conf_conn_flags_filtered()` (Filter Enabled, Block All, the DNS ports, Block Internet/LAN, the LAN and Internet address groups) returns TRUE when it decides the connection alone, then the App isn't checked: no flow context (no traffic, no Speed Limits) and no new App logged. Else `fort_callout_ale_check_app()` finds the App's data and `fort_conf_conn_app_allowed()` decides (an `act.blocked` already unset is allowed at once: the Filter Disabled with the traffic collected, an allowed Internet address; then Fort Firewall's Service, `conn->is_fort_service`, is allowed and permitted hard while `dns_forwarder_enabled`); an allowed connection gets its flow context, a blocked one may be asked (`fort_callout_ale_ask()`), an unknown App is logged as new (`fort_callout_ale_log_app_path()`). Then the connection is logged by the conf's and the App's log flags (never with `FORT_CONN_REASON_UNKNOWN`), an allowed flow's CONN not logged by them goes as `FORT_LOG_CONN_ACTIVITY` (for the Activity only, not the conn DB: it may have `FORT_CONN_REASON_UNKNOWN`, the Filter Disabled with the traffic collected), and the connection is classified. The UI's `DriverCommon::confConnFilter()` runs the same checks without the flows and the logging, so its result doesn't show whether the flags or the App decided: a test of that calls `fort_conf_conn_flags_filtered()` (`ConnFilterTest::connFlagsFiltered()`). A Zones callback (`fort_devconf_zones_ip_included()`) takes the conf's spin lock on each call: call it only with a zones mask (cf. `fort_conf_conn_zone_filtered()`).

Traffic accounting, the WFP provider and the flows' log: `driver.md`.
